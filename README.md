# 一炮定江山 —— 看看你能到第几关

> 仓库目录名仍是 `color-brick-cannon`；界面标题与浏览器标签页用的都是这句。

3D 物理破坏解谜小游戏。你操控一台彩色炮台，用有限的弹药把远处的砖墙、叠塔、拱门轰塌，完成每关目标。

**界面默认中文，首页可一键切换中 / 英文**（选择会记住，刷新不丢）。

纯前端项目，**构建产物是单个自包含的 `index.html`**，可以直接丢到任意静态托管（Vercel / GitHub Pages / 对象存储 / 甚至双击本地打开）。

---

## 快速开始

```bash
npm ci          # 按锁文件安装依赖（102 个包，约 123MB）
npm run dev     # 开发服务器，默认 http://localhost:5173
npm run build   # 生产构建 → dist/index.html（单文件，约 944KB / gzip 259KB）
npm run preview # 本地预览构建产物
```

类型检查（**当前 0 错误**）：

```bash
npx tsc --noEmit
```

> ⚠️ `npm run build` 只跑 `vite build`，走 esbuild 转译，**不做类型检查**。改完代码想确认类型安全必须单独跑 `tsc --noEmit`。

## 操作方式

### 电脑（鼠标 / 键盘）

| 输入 | 作用 |
|---|---|
| 移动鼠标 | 瞄准（水平 yaw ±60°，仰角 pitch −5° ~ 75°） |
| 左键点击 / 空格 | 开炮（有 0.45s 装填冷却） |
| `A` `D` | 左右旋转炮台 |
| `W` `S` | 上下调整仰角 |
| `Q` `E` | 减小 / 增大力度 |
| 鼠标滚轮 | 微调力度（每格 ±1.5） |
| 滑杆 | 直接设定力度（0~100% 映射到 20~60 初速度） |
| 右下角「切换弹药」按钮 | 循环切换 4 种弹药（标准 / 铁锤 / 爆破筒 / 三连发） |
| `R` | 重开当前关 |
| `Esc` | 暂停 / 继续（暂停面板内含关卡选择） |

### 手机 / 平板（触屏）

| 输入 | 作用 |
|---|---|
| 手指按住画面 | 进入瞄准态（准星放大变黄 + 屏幕提示「瞄准中 · 松手发射」） |
| 按住时左右拖 | 旋转视角（手指右滑 → 视角右转） |
| 按住时上下拖 | 调仰角（手指上滑 → 抬高炮口） |
| **手指松开** | **发射** |
| 底部滑杆 | 先调好力度（发射前调，拖动时轨迹线会跟着变） |
| 右下角「切换弹药」按钮 | 循环切换 4 种弹药 |
| 右上角 ⏸ / ⟳ | 暂停 / 重开本关 |

几条容易踩的细节：

- 触控是**相对拖动**：按下的一瞬间视角不会跳到手指所在位置，是从当前角度接着转。
- 灵敏度与鼠标一致（滑过整个屏幕宽 = 转 110°），改手感只调 `Game.ts` 里的 `TOUCH_SENS`。
- 只有按在**画面**上才瞄准；按到 HUD 面板（暂停 / 重开 / 滑杆）不会。
- 多指按下去只有**第一根**手指管瞄准，第二根不会打断，也不会误发。
- 来电、系统手势打断时**不会**发射（只退出瞄准态）。
- **默认仰角 22° 下直接就能瞄**：砖墙与预测虚线都完整可见（相机已在 2026-09-23 修过，原先此时炮身会把两者全部挡住）。

界面上还有两个开关：**轨迹线 / Trajectory**（抛物线预测虚线）、**音效 / Sound**（WebAudio 实时合成，零音频素材）。

## 弹药（4 种）

右下角那颗按钮原先写「发射」，但鼠标点画布 / 空格 / 触屏松手都能发射，它其实是多余的 —— 现在改成**切换弹药**（循环，顺序见 `ammo.ts` 的 `AMMO_ORDER`）。暂停面板里还有一份**弹药图鉴**，把四种的差别写全了（按钮上只放得下名字）。**弹药选择跨关卡保留**，切弹药**不消耗**弹药数 —— 它是「选打法」，不是「用道具」。

| 弹药 | 半径 | 质量 | 初速倍率 | 一次发射 | 定位 |
|---|---|---|---|---|---|
| `standard` 标准弹 | 0.45 | 9 | ×1.0 | 1 | 基准。其余三种都是跟它比 |
| `hammer` 铁锤弹 | 0.62 | 18 | ×0.88 | 1 | 撞得动厚墙与平台边缘；代价是射程只剩约 77%，得把力度调高 |
| `bomb` 爆破筒 | 0.5 | 11 | ×1.0 | 1 | **碰到东西当帧就炸**（无引信延迟），范围 3.4m，拆玻璃与密集砖最狠。命中时有专门的**加性特效层**（爆心闪光 + 冲击波环 + 碎石 + 尘埃 + 闪光灯），见 `ART_DIRECTION.md` 5.4 / 11.7 |
| `triple` 三连发 | 0.32 | 5 | ×1.0 | 3（左右各偏 7°） | 单颗动能只有标准弹一半；胜在能同时够到三个分开的承重单元 |

所有物理参数只有一处 —— `src/game/ammo.ts` 的 `AMMO` 表（文案留在 `i18n.ts`，引擎不产出界面文案）。

三条实现上的硬规矩（改弹药前先读 `HANDOVER.md` 的对应条目）：

- **散射偏移作用在 `yaw` 上再重算整个方向向量**，不能只给 `dir.x` 加个数 —— 那样连仰角一起改了，弹道会整体变平。见 `Game.aimDirAt()`。
- **爆炸按「速度增量」施加，不是写死冲量**。冲量的实际效果是 `impulse / mass`，而砖块质量在 1.0~1.8 之间浮动，写死冲量会让轻砖飞天、重砖不动。所以先算 `Δv`（**边缘线性衰减到 0**），再乘该砖的 `mass` 换算成冲量。
- **爆炸必须在 `world.step()` 之后执行**（放在炮弹清理段），与玻璃碎裂同一条纪律 —— 碰撞回调发生在 step 内部，那时求解器还握着 body。

还有两个容易漏的细节：

- **爆破筒是接触引爆，没有引信延迟**：碰到东西当帧就炸（`collide` 回调只置标记，`world.step()` 之后兑现）。阈值（法向速度 > 1.5）只用来放过纯擦碰，不是引信。⚠️ 早先版本是「命中后烧 0.3s 引信」，实测在现有关卡上**几乎无效** —— 关卡都是「薄壳 + 一块平台」，纵深只有一两块砖，球碰到外壳时已经在结构外面，再飞 0.3 秒（时速 40 米 ⇒ 12 米）就整个掠过去了。
- **爆炸必须显式判玻璃碎裂**：悬空的玻璃砖被炸飞之后只会飞出去，**永远等不到那次碰撞**，所以爆炸里要直接按 `Δv > GLASS_BREAK_V` 判碎。
- **爆炸后要再清一次碎裂队列**（第二次 `drainShatters()`，在 `checkKnocked()` 之前）—— 爆炸可能刚把某块玻璃判碎，不清的话同一块砖会被记两次账。
- **`explode()` 内部有一条硬分界线**：一条写着「以下是纯表现，一行都不影响上面算出来的物理」的注释，上面是物理段（`EXPLOSION_RADIUS` / `EXPLOSION_DV` / 玻璃判碎），下面是表现段（闪光灯脉冲 + `spawnBlastFx()` + 三批 `emit()` + 震屏 + 音效）。**调爆炸观感只在分界线之后改**；碰了分界线之前的值，必须重跑 `node tools/playtest.mjs --ammo bomb` 复核难度（全 10 关约数分钟）。

> **加第五种弹药要动的 5 处**（清单写在 `ammo.ts` 顶部）：① `AmmoKind` 加一个字面量 + `AMMO` 表加一条 ② `Game.ts` 里若它是新行为（像爆破筒那样）才要加分支 ③ **`tools/playtest.mjs` 的 `AMMO` 表必须同步** —— 漏了**不报错**，工具会静默按标准弹算，给出的「一发最好」与真机不符 ④ `i18n.ts` 的 `ammoName` / `ammoDesc` 补中英两条 ⑤ 教程引导里补一句。

## 挑战模式

教程浮层与暂停面板各有一个 **⚡ 挑战模式** 开关。打开后**每关只有 1 发炮弹、一发定胜负**，失败即重来；HUD 左上角会出现紫色徽标，弹药指示变成 1 颗。

判定规则写在**关卡数据**里（`levels.ts` 的 `LevelDef.challenge?: ChallengeRule`），而不是散在引擎里：

| `judge` | 判据 | 用在哪 |
|---|---|---|
| `'complete'` | 与普通模式同一判据：一发就达成了关卡目标 | 默认（关卡不写 `challenge` 就是这个） |
| `'score'` | 一发得分达到 `scoreLine`，**或** 一发直接完成了目标 | L4（550）· L7（1800） |

为什么要 `'score'` 这一档：**L4** 的四块红砖全堆在挡板后面的高台上（`x = 5.5 ~ 8.5`），一发最多只吃得到一侧；**L7** 的两颗紫色目标分列 `x = ±7`，一发在物理上不可能同时命中。这两关如果按 `'complete'` 判，在挑战模式里**永远通不过** —— 不是难，是不可能。

两条配套的取舍：

- **`scoreLine` 的取值法**（**2026-09-24 修订**）：跑 `tools/playtest.mjs` 拿到**单发最高分**，取它的约 **50%**，再取整到 50。
  旧公式 `一发最好 × 100 × 0.6`（L4：9×100×0.6 → 550；L7：14×100×0.6 → 850）**只数砖块、漏算连击奖励** —— 实测 L7 那一发实际拿 **3675** 分（14 块全落在同一条 1.6 秒连击链里），850 等于「发挥 23% 即通过」。现 L7 = **1800**（≈ 打掉 9 块且全连击）。
- **挑战模式通过也会解锁下一关**（`markCleared`），但**不写普通模式的星级**（`recordStars` 只在普通模式调）。两套记录完全独立，互不写入。

> ⚠️ **加新关卡时要自查一句**：「这一关的目标，一发能不能同时达成？」不能就必须写 `judge: 'score'`，否则这关在挑战模式里永远通不过。这句自查写在 `levels.ts` 里 `ChallengeRule` 的注释上。

## 关卡解锁与进度

**完成前一关才解锁下一关**（第 1 关永远可进）。锁住的关卡按钮是 `disabled` + 虚线边框 + 🔒 + 「未解锁」——不用「点了没反应」，玩家要能一眼看出是锁着而不是坏了。

进度整体落在 `localStorage['cbc:progress:v1']`：

| 字段 | 含义 |
|---|---|
| `cleared` | 逐关是否通关（**解锁门槛读它**） |
| `stars` | 逐关的最好星级（普通模式） |
| `challenge` | 逐关是否已通过挑战模式（与星级完全独立） |

三个写入函数（`markCleared` / `recordStars` / `markChallengePassed`）都是**幂等**的（已为 `true` / 星级没变高就直接 return），所以通关 effect 多触发几次没有副作用。

> ⚠️ 与语言的存储键（`cbc:lang`）**刻意分开**：清了进度不该把界面语言也重置掉，这是两件互不相关的事。
> ⚠️ 键名带版本号（`:v1`）。改数据结构就升到 `v2`，旧档读不出来会被 `normalize()` 补成合法形状（长度对齐关卡数、类型兜底、星级钳到 0~3），**不会**让玩家碰到 `undefined` 崩溃。
> ⚠️ 快照对象每帧都会被 React 拿去比引用，所以只在真正改动时**整体替换**它 —— 不能就地 mutate（那样引用不变，`useSyncExternalStore` 的订阅者收不到通知）。
> ⚠️ **进度快照是在模块加载时读一次**（`let current = load()`）。所以给测试种进度必须在页面 `navigate` **之前**写完，加载之后再改是无效的。

## 界面语言

默认 **中文**，首页（教程浮层）中部有 `中文 | English` 切换按钮，**暂停面板底部也有一个**（这样切错语言不用刷新就能切回来）。

| 行为 | 落地方式 |
|---|---|
| 文案存放 | 全部集中在 `src/i18n.ts`，一处文案 = 一份 `{ zh, en }` 对照 |
| 关卡名 / 关卡提示 | 放在 `levels.ts` 的关卡数据里，同样是 `{ zh, en }` 结构 |
| 关卡目标文案 | **不写死**，由 `objectiveText(objective, lang)` 按 `kind / count / color` 现场拼出 —— 改了关卡数值文案不会跟着对不上 |
| 默认值 | `zh`；未做过选择的用户进来就是中文 |
| 记忆 | 切换后写入 `localStorage['cbc:lang']`，刷新 / 重开浏览器仍生效 |
| 附带同步 | `<html lang>` 与标签页标题（`document.title`）一起切换 |
| 切换方式 | `useLang()`（内部是 `useSyncExternalStore`），所有读它的组件立即重渲染 |

**加一门语言**：给 `Lang` 加一个字面量 → 在 `UI` 里补齐同名字段 → 在 `COLOR_ZH` 补颜色词。其余代码不用动。

> 引擎层（`Game.ts`）**不产出任何界面文案**。它只通过 `HudState` 传数值与 `level` 序号，UI 自己按序号查表取文案。这样切换语言时界面会立刻更新，不存在「引擎里残留上一门语言字符串」的问题。

## 玩法规则

**目标类型**（`levels.ts` 里的 `Objective.kind`）：

| kind | 含义 | 使用关卡 |
|---|---|---|
| `knockCount` | 砸倒 N 块砖 | L1 / L3 / L5 / L6 / L8 / L9 / L10 |
| `targets` | 砸掉所有带 `target` 标记的砖（紫色宝石） | L2 / L7 |
| `color` | 砸掉 N 块指定颜色的砖 | L4 |
| `knockAll` | 砸掉全部非静态砖 | *未使用（预留，`i18n.ts` 已有对应文案模板）* |
| `score` | 达到目标分数 | *未使用（预留）* |

**砖种**（`levels.ts` 里的 `BrickKind`，与「砖形 `BrickShape`」正交 —— 方块 / 圆柱 / 宝石任意形状都能是玻璃）：

| kind | 外观 | 受击行为 | 用在哪 |
|---|---|---|---|
| `solid` | 不透明彩色砖（默认） | 被撞后照常翻倒 / 位移 | 除下述 20 块之外的全部砖 |
| `glass` | **半透明**浅色砖（`opacity 0.6` + 高光 `shininess 130`），**不投影** | 撞击的**法向速度 > 3.0** 时当场碎裂并消失，**不再提供任何支撑** | L2 / L5 / L7 / L8 / L10，共 **20** 块 |

玻璃的「碎」是彻底的：从物理世界 `removeBody` + 从 `bricks` 数组 `splice`，所以它**不会**留在原地当障碍，也不会像普通砖那样开始「慢慢倒」——上面压着的东西会立刻失去支撑整片塌下来。计分走的是和普通砖同一条路（`markKnocked`）：一块玻璃 = 一块击倒，照常进连击。

> **加第三种砖种要动的地方**写在 `levels.ts` 顶部的注释里（5 条清单）：① `BrickKind` 加一个字面量 ② `art.ts` 加它的材质工厂（颜色 / 透明 / 高光一律收在 `art.ts`） ③ `Game.ts` 的 `addBrick` 里按 kind 选材质、有特殊行为就在碰撞回调里加判定 ④ `tools/` 的 `check-levels.mjs` 与 `playtest.mjs` 都要把新行为补进物理复刻 ⑤ `i18n.ts` 新手引导加一句。
>
> 投放方式也留好了扩展位：构件工厂接一个 `BrickPick = (ctx: {row, col}) => BrickKind | undefined` 选择器 —— 关卡里写 `pick: ({ row }) => (row === 1 ? 'glass' : undefined)` 就能把任意一层换成玻璃，**加新砖种不用改工厂签名**。

**「被砸倒」的判定**：砖块的位移 > **1.2**，**或者** 倾角 > **38°**（只看局部 Y 轴，所以绕 Y 轴的水平旋转不算倒）。

**计分**：
- 每块砖基础 100 分（带 `target` 的 300 / 400 分）。
- 连击窗口 **1600ms**：窗口内连续砸倒，第 n 块额外加 `基础分 × 25% × (n−1)`；连到第 5 块播放坍塌音效。
- 通关额外奖励 **剩余弹药 × 200**。

**星级**（结算时判定）：

| 星级 | 条件 |
|---|---|
| ★ | 完成关卡目标 |
| ★★ | 完成目标 + 剩余弹药 ≥ `twoStarAmmoLeft` |
| ★★★ | 再满足 `score ≥ targetScore` |

> ⚠️ 注意：★ 判定里的 `score` **已经包含弹药奖励**（`finish()` 里先加奖励再比对），所以三星门槛实际比表面数字宽松。
>
> ⚠️ **挑战模式下星级恒为 0**（`finish()` 里走单独分支，不写普通模式的星级，也不加弹药奖励 —— 挑战模式只有 1 发，那个奖励算式没有意义）。挑战的成败单独记在 `progress.challenge[]` 里。

**结束时机**：达成目标后不会立刻结算，需要等 `endTimer > 1.2s` **且** 场上物理全部静止（无球在场，所有非静态砖速度 < 0.6 或已休眠）。

**靶场景别**：关卡数据里写的是**设计坐标**（靶场落在 `z ≈ −30` 一带）。`levels.ts` 末尾统一加一个 `FIELD_SHIFT_Z`（当前 **6**）把整片靶场往炮台方向平移，导出的 `LEVELS` 才是真正用的坐标。所以「砖块离炮台太远」这类景别问题只改**一个常数**，不用逐关改几十处坐标。

> ⚠️ 这个位移**只动 z**（x / y 是承重高度，动不得）。改完 `FIELD_SHIFT_Z` 必须重跑 `check-levels.mjs` 与 `playtest.mjs` 两个物理工具 —— 距离一变，障碍拦截关系、弹道落角、单发覆盖率全都会变（本轮拉近 6m 后 L6 单发从 19 涨到 26、L9 反而从 28 掉到 17）。

**难度曲线（L6~L10 是新加的，刻意只加复杂度、不加难度）**

配平不是靠感觉，而是 `node tools/playtest.mjs` 逐个跑真实物理量出来的：对每关用「瞄准每座结构最低那几块砖反解出的弹道」各打一发，取**打掉最多砖的那一发**。这张表的判据是最后一列 —— **它应该落在同一带里**。

| 关 | 可击倒 | 目标 | 目标/可击倒 | 弹药 | 一发最好 | **一发/目标** | 弹药×一发/目标 |
|---|---|---|---|---|---|---|---|
| 1 | 26 | 8 | 31% | 5 | 20 | 250% | 12.5× |
| 2 | 18 | 1（目标物） | — | 5 | 18 | 1800% | 90.0× |
| 3 | 22 | 14 | 64% | 4 | 21 | 150% | 6.0× |
| 4 | 16 | 4（红砖） | 25% | 5 | 9 | 225% | 11.3× |
| 5 | 51 | 30 | 59% | 6 | 41 | **137%** | 8.2× |
| 6 | 38 | 18 | 47% | 5 | 26 | **144%** | 7.2× |
| 7 | 36 | 2（目标物） | — | 5 | 14 | 700% | 35.0× |
| 8 | 38 | 19 | 50% | 5 | 38 | 200% | 10.0× |
| 9 | 54 | 12 | 22% | 6 | 17 | **142%** | 8.5× |
| 10 | 65 | 28 | 43% | 6 | 47 | 168% | 10.1× |

> **这张表改过两次，两次都是同一个教训的不同侧面。**
>
> **第一次（初稿）：不能只看「目标占全场几成」。** 初稿 L6 目标 18、L9 目标 26 是按比例定的（47% / 48%，落在老五关 25%~64% 的带里），实测却发现这个比例**不充分**：L6 是「两座独立的塔 + 一块搭在两塔上的长板」，一发最多打掉其中一座塔加板上的东西（当时实测 19 块），它不可能像 L5 那样一发烧掉大半场。于是「一发/目标」只有 106%，比老五关里最紧的 L5（137%）还紧 —— 玩家得打出一发近乎完美的球才能一发过关。降到 14 后与 L5 持平。
> **判据应该是「最强的那一发能覆盖几成」，而不是「目标占全场几成」。** 结构越分散（多个独立承重单元），单发覆盖率越低，目标数就得跟着降。
>
> **第二次（本轮靶场拉近 6m）：拉近不等于所有关都变简单。** 距离一近，低仰角平射能一路犁过去，L6 的单发从 19 涨到 26（覆盖率 68%），所以目标从 14 **调回 18**；但 L9 是「左右对称两座塔楼 + 中间廊板 + 一道挡射线的矮墙」，**散开的独立承重单元对落点高度极敏感、平射带不出连锁**，单发反而从 28 掉到 17（覆盖率 31%），目标从 20 **降到 12**。
> 所以拉近之后 L6 / L9 往**相反**方向各调了一次 —— 凭「拉近了就都变简单」想当然会调错。
>
> ⚠️ 如果嫌 L9 的 12 看着配不上「倒数第二关」，正确做法是**改结构**（把那道挡射线的矮墙拆掉、让两座砦互相牵连）而不是把目标数调回高比例。

新五关的做法是「换结构组合 + 换承重关系」，不是「堆砖块数 + 砍弹药」：

- **L6 双塔** — 两块独立结构由一块长板连成一体：拆掉任一条腿，整块板连同上头的砖一起下来
- **L7 阶梯要塞** — 三个高度（平台 2.0 / 3.0 + 草地 0）各放一种结构（拱门 / 塔 / 墙），逼玩家切换仰角而不是拉满力度
- **L8 双层柱廊** — 三座拱门撑起长廊，长廊上再站两座小拱门 + 一块二层顶板；一层的连锁会传到二层
- **L9 双砦** — 左右对称的两座塔楼各自带目标，中间用一对拱门 + 廊板连起来，底下还压着一道矮墙挡射击线
- **L10 大教堂** — 集大成：两塔 + 中拱 + 拱心石共同托住一顶 22 米宽的大屋顶，屋顶上还有一堵墙和一颗目标；两翼另有两堵矮墙

**构件工厂**（`levels.ts`，用代码生成关卡，不手写坐标）：

- `wall(x0, y0, z, cols, rows, bw, bh, bd, pick?)` — 交错砌法的砖墙，`rainbow` 六色循环上色。**`x0` 是墙的左边缘**；奇数层用「两端半砖 + 中间整砖」收边，保证上下层外轮廓重合
- `tower(x, z, layers, base, y0, withTarget, pick?)` — 每层「双柱 + 顶板」，共 `layers` 层；`y0` 是起建高度（放平台上时必须传平台顶面）；`withTarget=false` 时不生成塔顶紫色目标（留给别的东西占位）
- `arch(x, z, h, span, color, y0, pick?)` — 两侧砖柱 + 顶部横梁，`y0` 是起建高度

三个工厂末位都接一个可选的 **`pick?: BrickPick`**，用来指定「这块砖是哪种砖」（不传就是默认的 `solid`）。**三种构件的 `row` / `col` 含义各不相同，投放前先看这张表**：

| 工厂 | `row` | `col` |
|---|---|---|
| `wall` | 第几层（0 = 最底） | 该层从左往右第几块（0 起算；奇数层的两端半砖分别是 `0` 与 `cols`） |
| `tower` | 第几层（0 = 最底） | `0` 左柱 / `1` 右柱 / `2` 楼板（塔顶紫色目标宝石不吃 `pick`） |
| `arch` | 第几块柱石（0 = 最底），**顶梁那块的 `row = cols`** | `0` 左腿 / `1` 右腿（顶梁恒 `0`） |

各关的玻璃砖就是靠这张表投的，例如 L7 把左台拱门两条腿的下两块换成玻璃（`h=3.6` ⇒ `cols=4`，`row 0/1` × 左右腿 = 4 块）：

```ts
arch(-7, -26, 3.6, 4.0, 'blue', 2.0, ({ row }) => (row < 2 ? 'glass' : undefined))
```

⚠️ **摆砖有一条硬约束**：每块砖的底面必须正好落在支撑面上（地面 / 静态平台顶面 / 下方砖块顶面），既不能悬空也不能埋进去。违反的话开局就会自行倒塌、白送击倒进度（L5 曾因此开局 0.5 秒直接胜利）。详见 `HANDOVER.md` 的陷阱六。

配色：色值只有三处 —— `art.ts` 的 `PALETTE`（低饱和受限调色板）：`red #d9544d` `orange #e08a45` `yellow #e7c169` `green #7fa96a` `blue #5d8fa8` `purple #8e6e9e` `gray #c9c0b2`（gray 用于静态承重件）；环境色 `ENV`；**特效色 `FX`**（爆炸 / 火星 / 炮口 / 烟尘，**刻意与 `PALETTE` 分开** —— `PALETTE` 是玩法色，红色意味着「这是 L4 要打的目标」，特效色一旦混进来这条读法就失效了）。关卡数据里只写颜色**名**（`ColorKey`），不写色值。完整规范在 `ART_DIRECTION.md`。

**玻璃砖不需要新色值**：它沿用所属砖的颜色名，由 `glassMaterial(color, variant)` 把该色向 `ENV.glass`（`#d6f0f5`）**混合 75%** 再调透明 —— 所以「蓝色的玻璃柱」看起来是淡青蓝而不是饱和大蓝，一眼能和同色实心砖区分开。想改玻璃的观感只调 `ENV.glass` 一个值。

```bash
node tools/check-levels.mjs 5      # 也可以只查某几关（快得多）

node tools/check-levels-live.mjs   # 可选：完整真机回归；需先起静态服务 + headless Chrome
```

**三个脚本都把游戏逻辑复刻了一份**，改游戏代码时要注意它们：

| 抄了什么 | 在哪 | 什么时候必须同步 |
|---|---|---|
| 物理常量（重力 / 求解器 / 四组接触材质 / 阻尼 / 击倒阈值 / 炮弹寿命与上限） | 三个脚本的顶部常量区 | 改 `Game.ts` 的物理参数 |
| **玻璃碎裂机制**（`GLASS_BREAK_V = 3.0` + 排队 + 逐帧清算） | `check-levels.mjs` · `playtest.mjs` | 改玻璃行为 / 加新砖种。**漏了会静默失真**：玻璃在复刻里变成永不碎的实心砖，自检却照样全绿 |
| **弹药表**（半径 / 质量 / 初速倍率 / 发数 / 散射 + `BOMB_TRIGGER_V` / `EXPLOSION_RADIUS` / `EXPLOSION_DV`） | `playtest.mjs`（`AMMO` 表） | 改 `ammo.ts` / 加新弹药。**漏了不报错**：工具会按标准弹静默算出一个与真机不符的「一发最好」。`check-levels.mjs` **不开炮**，不需要复刻 |
| 关卡坐标 / 目标数 / 弹药 / 玻璃位置（`EXPECT` 表与 `GLASS_SHOTS`） | `check-levels-live.mjs` | 改关卡数值 / 改 `FIELD_SHIFT_Z`。**不同步就会打空**，断言的「得分上涨」会 FAIL |

> ⚠️ `check-levels-live.mjs` 现在会**先断言解锁门槛、再种一份全通关进度**，最后才逐关回归 —— 因为门槛（`progress.ts` 的 `isUnlocked`）会让「新档」下只开第 1 关，不种进度就点不进其它关。种进度用的是 `cbc:progress:v1`，必须在 `navigate` **之前**写（进度快照是模块加载时读一次的）。
>
> ⚠️ 断言里读 HUD 数字时**必须先确认拿到的是数字**。`Runtime.evaluate` 超时 / 页面抛异常时返回的是**字符串**，而字符串取 `.score` 得 `undefined`、再被 `?? 0` 静默吞成 `0` —— 断言会以「0 → 0」的形式**假失败**（截图里其实早就 4850 分了）。脚本里的 `numOf()` 就是干这个的。

> ⚠️ **改 `FIELD_SHIFT_Z` 之后必须重跑 `check-levels.mjs` + `playtest.mjs`**：距离一变，障碍拦截、弹道落角、单发覆盖率全变，配平可能整体失衡（本轮就是靠这一步发现 L6 / L9 需要往相反方向各调一次）。

**数据流**：`Game` 每帧在自己的 `step()` 末尾调用 `onHud(state)` 把 HUD 快照推给 React，`App` 用 `JSON.stringify` 比对做短路，只在真正变化时 `setState`。UI 反向下发通过直接调 `game.fire() / reset() / setPower() / loadLevel()`。

**文案流向**：`Game.ts` 传 `level`（1 基序号）与 `objectiveProgress`（纯数字，如 `3 / 8`）；`App.tsx` 用 `LEVELS[hud.level - 1]` 取到关卡定义，再用 `resolve(lv.name, lang)` / `objectiveText(lv.objective, lang)` 转成当前语言的文案。**引擎不碰 `lang`**。

**暂停语义**：`game.paused = paused || tutorial`。暂停时 `step()` 整个不跑（物理、输入、HUD 一起冻结），但 `render()` 仍在跑，所以画面不黑。

## 部署到 Vercel

**可以，而且是最省事的方案。** 这是纯静态站点，不需要任何服务端函数、不需要环境变量、不需要数据库，Vercel 免费额度完全够用（构建产物只有一个 939KB 的 HTML）。

仓库内已备好 `vercel.json`（显式声明 framework= vite / buildCommand / outputDirectory，其实不写 Vercel 也能自动识别 Vite）。

### 方式 A：接 GitHub（推荐，之后 push 即自动部署）

1. 本地初始化仓库并推送到 GitHub（**这一步由你本人执行**）：

   ```bash
   git init
   git add .
   git commit -m "chore: initial commit"
   git branch -M main
   git remote add origin <你的仓库地址>
   git push -u origin main
   ```

   `.gitignore` 已配置好，`node_modules/` 与 `dist/` 不会进仓库。

   > ⚠️ **首次提交务必用 `git add .`（或 `git add -A`），不要只 add 你改动过的那几个文件。**
   > Vercel 是读 `package.json` 来判断项目类型的：仓库里一旦缺它，构建会直接死在
   > `npm error enoent Could not read package.json: /vercel/path0/package.json`，
   > 同时 Framework Preset 会只剩 `Other` 一个选项。这两个现象是同一个原因。
   > 推之前用 `git status --short` 扫一眼，确认 `package.json`、`index.html`、`src/` 都在列表里。

2. 打开 [vercel.com/new](https://vercel.com/new)，选 **Import Git Repository**，选中这个仓库。
3. Framework Preset 会自动识别为 **Vite**；确认 Build Command = `npm run build`、Output Directory = `dist`，直接 Deploy。
4. 约 1 分钟后拿到 `https://<项目名>.vercel.app`，可以直接分享给别人玩。

### 方式 B：不用 GitHub，直接 CLI 部署

```bash
npx vercel        # 首次会引导登录 + 关联项目，产出预览地址
npx vercel --prod # 部署到正式域名
```

### 部署报错排查

| 报错现象 | 原因 | 处理 |
|---|---|---|
| `ENOENT: ... open '/vercel/path0/package.json'` 且 Preset 只能选 `Other` | 仓库里没有 `package.json` —— 首次提交漏推了文件 | 补齐文件后 `git push`，Vercel 自动重新部署 |
| 构建成功但访问 404 | `Output Directory` 与实际产物目录没对上 | 确认 Output Directory = `dist`（本仓库 `vercel.json` 已声明） |
| Preset 显示 `Other` 但构建正常 | 项目创建时 Vercel 没识别出框架 | 无需处理 —— `vercel.json` 里的 `framework: "vite"` 会覆盖预设。想收拾干净就在 Settings → Build & Development Settings 手动选 Vite，或删掉项目重新 Import |
| `Unsupported engine` / Node 版本报错 | Vite 7 要求 Node ≥ 20.19 或 ≥ 22.12 | `package.json` 已声明 `"engines": { "node": "22.x" }`，Vercel 会据此选运行时 |

- **手机触控瞄准**（2026-09-23）：输入层由 `mousemove` / `mousedown` 换成 **Pointer Events**，按 `pointerType` 分流 —— 鼠标保持原来的「绝对位置跟随 + 点击即发射」，触控则是「**按住拖动旋转视角 + 松手发射**」。配套处理了：`touch-action:none`（否则拖动会被浏览器当成滚动）、`setPointerCapture`（手指滑出画面再松手也能收到事件）、多指只认第一根、`pointercancel`（来电 / 系统手势）不发射、装填冷却期内按住不进瞄准态。UI 加入瞄准态反馈（准星放大变黄 + 「瞄准中 · 松手发射」）与窄屏响应式布局、触屏专属操作说明。
- **中英双语界面 + 语言切换**（2026-09-23）：新增 `src/i18n.ts`，默认中文，首页与暂停面板各有切换按钮，选择持久化到 `localStorage['cbc:lang']`。同时把界面文案从引擎里剥离（`HudState` 不再含 `levelName` / `objective`），`levels.ts` 的 `Objective.text` 改为按数值派生。
- **`Game.reset()` 漏清炮弹**（2026-09-23 修复）：原代码 `for (const b of this.balls) this.removeBall(b)`，而 `removeBall` 内部会 `splice(this.balls)`，导致 `for...of` 的迭代游标跳过一半元素。残留的炮弹**既留在 cannon-es 物理世界里继续参与碰撞，又留在场景中不再同步网格**（表现为一颗冻结的黑球立在原地）。改为迭代副本 `[...this.balls]`。复现方法：连开 2~3 炮后按 `R`。

### 2026-09-23 三处修复（相机遮挡 / 关卡初始摆放 / 炮管朝向）

这三项是同一轮排查出来的，彼此独立，但都是「症状看得见、根因在别处」那类问题。

**① 相机遮挡（`Game.ts`）**

原写法把相机沿**瞄准方向**后退：`camPos = 炮台 + aimDir × (−6.5) + 世界up × 2.6`。`aimDir` 带着 `sin(pitch)`，于是**仰角越高相机越矮**：22°（默认）时相机高度只剩 1.77，40° 时 0.02（贴地），75° 时 **−2.08（钻到地面以下）**；水平距离同时从 6.5 缩到 1.68。结果就是默认视角下炮身横在画面中央，把砖墙和轨迹线全部挡住。

改成**水平后退 + 固定离地高度**：`CAM_BACK = 5.5`、`CAM_HEIGHT = 3.4`。射线检测实测遮挡率（默认 22°）：

| | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|
| 修复前 | 100% | 70% | 97% | 11% | 54% |
| 修复后 | 0% | 0% | 0% | 0% | 0% |

并且 0°~75° **全仰角**都是 0%，相机不再入地。参数是扫出来选的：`height` 从 2.2 提到 3.4 就够，再高也只是让炮台更快退出画面，而**炮身露出比例几乎不随相机高度变化（28%→20%）**，所以抬高相机的代价极小。

> ⚠️ 不要把相机改回「沿 `aimDir` 后退」。这是本轮唯一的构图红线。

**② 关卡初始摆放（`levels.ts`）**

开局静置 3 秒、零操作，被判「击倒」的砖块数：

| | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|
| 修复前 | 1/24 | 0/19 | 4/24 | 3/18 | **31/55（0.5 秒内直接胜利）** |
| 修复后 | 0 | 0 | 0 | 0 | 0 |

五类病根，全部消除：

- **埋入支撑体**：`tower()` / `arch()` 一律从 `y=0` 起建，而 L2 / L5 的静态平台顶面在 0.5 / 0.6 —— 柱底埋进平台，求解器要把它顶出来，整座结构被掀翻。两个工厂现在都接 `y0` 参数，关卡显式传平台顶面高度。
- **互相重叠**：L5 大横板与两个 target 圆柱各重叠 0.528 m³。
- **悬空自由落体**：L3 橙板悬空 4.15m、L4 桥板 6.10m、L5 那面墙 3.42m。
- **层间留缝**：`wall()` 用 `bh` 当行距、砖高却取 `bh * 0.95`，每层 0.04 的缝让整面墙微沉，把最外侧那块晃到 39°（判定阈值 38°）。改为高度取满 `bh`，水平方向仍留 3% 缝防穿插。
- **错缝凸出**：奇数层原先把整砖整体平移半块，两端各凸出半块，而这半块**正下方是空的** → 开局 0.6 秒自己倾覆。改成**两端半砖收边**，上下层外轮廓逐毫米对齐。

**L1 新增基座石台**（`pos [0, 0.3, -26]`，`size [12, 0.6, 2.4]`，顶面 y=0.6）：砖墙砌在台上，砖掉下来有 0.6m 落差，「被打落了」一眼可辨——原先直接砌在草地上，砖块落不落不直观。

> ⚠️ `levels.ts` 顶部有一段**摆砖硬约束速查**（各工厂的高度推导公式）。加构件前先按它算一遍「底面 = 支撑面」，这次的坑全在那一句里。

**③ 炮管朝向写反（`Game.ts`）**

`barrel.rotation.x = -degToRad(pitch)` 多了一个负号，导致炮管的**视觉朝向和弹道方向相反**：pitch 22° 时炮口世界 y = 0.33（应为 2.87），炮管朝下 22°、炮弹朝上 22°，差 44°。符号去掉即可。这个 bug 一直存在，只是被相机问题掩盖着——修好相机后炮身完整露出来才显形。

### 待确认 / 待决策（未改动）

- **⚠️ 关卡缺少纵深**（2026-09-24 爆破筒改动时暴露，未处理）：10 关里有 9 关是「薄壳 + 一块平台」——砖块基本沿 `z` 一个平面排开、只有一两块厚。直接后果有两层：① 所有武器的**穿透属性都没意义**（球擦到外壳就已经在结构外面了，这正是爆破筒原先那个 0.3s 引信失效的原因）；② 关卡之间的差异只能靠「横向铺开」做（L5 51 块、L10 65 块），而单发覆盖率已经顶到 95~100%（判据二的 `E_max` 瓶颈）。改法属于 **M1 / M3** 的活：给关卡加**前后错层**（承重单元放在不同 `z` 上）与**有厚度的墙**（2~3 块深）。⚠️ 不要用「给武器加延迟」去掩盖它（`GAME_DESIGN.md` 第 10.4 节的反模式）。
- **L4 红砖配平**：目标是「砸掉 4 块红砖」，但场上一共有 **5 块**红砖（4 块手写 + 1 块来自 `wall()` 的 rainbow 上色），所以目标比「砸掉全部红砖」更宽松。属配平细节，不是 bug。改法二选一：目标提到 5，或把 `wall()` 的颜色序列打散掉红色。
- **HUD 右上角的星星是误导性的**：它按 `score / targetScore` 粗估（>50% 给 2 星、≥target 给 3 星），而真实星级规则看的是**剩余弹药**。两者不是一回事。但它也是局内唯一的星级反馈，直接删掉会失去信息，需要先想清楚改成什么（比如改成进度条）。
- **⚠️ playtest 的解算网格含「鼠标够不到」的仰角**（2026-09-24 发现，未处理）：`playtest.mjs` 的 `PITCHES` 有 8 / 20 / 32 / 44 / 56 / **68** 六档，而鼠标瞄准的映射是 `pitch = -ny·90 + 20`（`ny ∈ [-0.5, 0.5]`，画布覆盖全视口）⇒ **鼠标最多只能瞄到 65°**（`PITCH_MAX` 写的是 75°，只有按 `W` / `S` 才够得到）。所以工具报出的「一发最好」有可能落在玩家用鼠标点不出来的弹道上（挑战模式回归时就撞到过这个：L1 的最优解正好是 pitch 68°）。两条修法二选一：把 `PITCHES` 的 68 换成 64（对齐鼠标上限），或把鼠标仰角映射放宽（改 `onPointerMove` 里那对系数）。**在此之前，别拿 pitch 68 档的数字去定关卡难度。**
- **右下角弹药按钮的「1 / 4」与右上角炮弹数的「1 / 5」容易混**（2026-09-24 发现，未处理）：两处都写成 `n / m` 的形式，但一个是「第几种弹药」、一个是「还剩几发」。颜色点在读得懂的前提下能区分，但窄屏上两块卡离得近时容易看错。可选的改法：把弹药按钮的角标改成「第 1 种」这种文字，或干脆去掉（图鉴里已经写清了）。
- **弹药耗尽后最长空等约 9 秒**：判负要等 `allSettled()`，而炮弹要 9 秒才超时回收，最后一炮落地后如果它停在界内，会等满 9 秒才弹结算面板。
- **失焦时按键卡住**：`keydown` / `keyup` 没有 `blur` 兜底，按住 `W` 时切走窗口，炮台会一直转。
- **无 `ResizeObserver`**：只有 `window.resize` 监听，拖动 DevTools 停靠导致容器变小、而窗口尺寸没变时，canvas 不会跟着缩放。
- **⚠️ 资源所有权（2026-09-23 美术重构后已反转，理解反了会出大问题）**：现在 `art.ts` 的几何体与材质**全部带缓存、被多个对象共享**，所以 `reset()` / `removeBall()` **绝不能** dispose 它们 —— 那会把别处正在用的同一份资源释放掉，症状是整场物体消失、渲染异常，**而且不报错**。共享资源统一在 `disposeArt()` 收口；**唯一例外**是每颗粒子独占的材质（`fadeMaterial()`）和每颗炮弹独占的尾迹几何体。详见 `HANDOVER.md` 陷阱四。
- **装饰物没有物理体**：树 / 岩石 / 草丛只是视觉道具，炮弹会直接穿过去。它们已被限制在射击走廊之外布点（`|x| > 24` 或 `z < -40`），正常情况下打不到，只有擦到边界时看起来会像穿模。
- **`src/utils/cn.ts` 是死代码**：脚手架残留，从未被 import。
- **两处无用分支**：`Objective.kind` 的 `knockAll` / `score` 无关卡使用（`i18n.ts` 已给它们备好中英文模板）；`evaluate()` 里 `finish(false)` 之前那句 `this.endTimer += dt` 是死代码。
- **`reset()` 里清粒子的循环同样建议改成迭代副本**（当前不 splice 所以没有 bug，但写法上是个陷阱）。
